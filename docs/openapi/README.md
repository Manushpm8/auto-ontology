# OpenAPI specs

Generated files — do not edit by hand. Each is committed so it can be reviewed
in a pull request diff and consumed without a running server; CI regenerates
them and fails if what you committed is stale.

| File | Describes | Generated by |
| --- | --- | --- |
| [`gsf-api.json`](./gsf-api.json) | **The public API.** 76 operations across 54 paths. | `pnpm openapi` (from `frontend/`) |
| [`backend.json`](./backend.json) | Internal GSF FastAPI app — 56 operations. | `uv run python -m dev_tools.generate_backend_openapi` |
| [`ingestion.json`](./ingestion.json) | Internal Ingestion Service FastAPI app — 6 operations. | same as above |

## Which one do consumers want?

`gsf-api.json`. The Python services are ClusterIP-only and reachable solely
through the Next.js proxy, so `backend.json` and `ingestion.json` describe an
internal surface nobody outside the cluster can call. They exist because
`gsf-api.json` is built partly from them.

`gsf-api.json` also carries things the FastAPI specs cannot know:

- `x-gsf-permissions` — the permission a caller needs, read from each route's
  `withPermission({...})` wrapper (or `"public"` for `withPublic`), plus the
  401/403 responses that implies.
- `x-gsf-source` — the `route.ts` that serves the operation.
- `x-gsf-proxied` — whether the handler forwards to FastAPI or answers itself.
- `x-gsf-upstream` — for the chat routes, the backend path whose response is
  relayed.

## How it is built

`frontend/scripts/generate-openapi.ts` walks `frontend/app/api/**/route.ts` with
ts-morph — file-based routing makes the paths deterministic — and fills in
schemas from two sources:

- **Proxied handlers** (`proxyToBackend`) forward the pathname verbatim, so
  their schemas are merged from `backend.json` by matching path and method.
- **Everything else** — the Prisma-backed handlers, which have no FastAPI
  counterpart, and the chat handlers, which build their own upstream request —
  declares its shapes in a sibling `app/api/**/openapi.ts` module using zod.
  See `frontend/types/openapi.ts` for that contract. The declaration lives
  beside `route.ts` rather than inside it because a plain Node script cannot
  import a route handler (`next/headers`, `after()`, `getPrisma()`).

Only the component schemas the public spec actually references are copied over,
closed transitively.

## Regenerating

```sh
uv run python -m dev_tools.generate_backend_openapi   # backend.json, ingestion.json
cd frontend && pnpm openapi                           # gsf-api.json
```

Run them in that order — the public spec reads the committed `backend.json`.

## Viewing

There is no OpenAPI renderer on GitHub. Locally:

```sh
npx @redocly/cli@1 preview-docs docs/openapi/gsf-api.json
```

Or paste the file into <https://docs.scalar.com/swagger-editor>.

## Known limitations

- No `securitySchemes` or `servers` block yet: the spec says which permission an
  operation needs, but not how to authenticate or against which host.
- Most schemas carry `additionalProperties: true`. Backend response models are
  deliberately permissive — FastAPI *drops* undeclared fields when a
  `response_model` is set, so a strict model would silently break responses
  rather than merely document them. Listed fields are reliable; the list is not
  guaranteed exhaustive.
- `PATCH /api/nodes/{node_id}` returns `object | null`: its shape depends on
  which properties the request patched.
- Every path, parameter, request body and response field is snake_case. The
  Prisma models that back the frontend-only routes use snake_case field names
  too, so a row serialises straight to the API shape; the Better Auth models
  (`User`, `Session`, `Account`, `SsoProvider`) keep their generated camelCase
  and are mapped at the handler.
