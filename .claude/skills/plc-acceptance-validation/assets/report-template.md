# PLC Acceptance Validation Report Template

Use this template when generating the acceptance validation report. Replace all
`<placeholder>` values with actual content. Status values are the exact strings
`PASS`, `FAIL`, `UNVERIFIED`, `MISSING`, `N/A` — no synonyms.

Save the rendered report to `agentic_plc/work_products/<feature-name>/acceptance-validation.md` in workspace mode, otherwise `.plc/briefs/<feature-name>-acceptance-validation.md`.

## Status Application Reminders

- Apply the status vocabulary in `SKILL.md` → *Status Vocabulary* exactly.
- **For an AC with no test pointing at it, status is UNVERIFIED at best, never PASS** — even if the implementation "obviously works".
- An AC with mixed-outcome pointers is FAIL. Never quietly pick the best pointer.
- N/A requires a recorded reason in the brief. Cite it.

## Severity Application Reminders

- Critical: Functional or Security AC, status FAIL or MISSING.
- Warning: NFR AC with FAIL/UNVERIFIED/MISSING; Functional AC UNVERIFIED; pointer present but unresolved (renamed/moved).
- Info: nice-to-have AC UNVERIFIED/MISSING; external pointer PASS where the brief already records a signoff.

Severity reflects the impact of the AC, not the strength of the verification gap.
